## 用户需求

用户拥有三个项目：`umd_components`（Vue 组件库，构建产出 UMD 文件）、`draggable`（拖拽式页面搭建前端）、`draggable-end`（Spring Boot 后端，尚未实施）。核心诉求：组件库构建生成后，如何把组件信息配置/注册到后端数据库，使拖拽前端能通过后端接口获取组件清单并动态加载组件。

## 已确认的方案决策

- **同步方案（方案 A）**：组件库通过 HTTP 上传接口提交「元数据 + 文件」，后端落盘指定目录并更新数据库，一次完成；不采用 Java 扫描目录方案（目录文件只有文件名、拿不到中文标题/描述元数据）。
- **本地开发文件提供**：后端 `file:` 静态映射直接指向组件库 `dist` 与根目录，构建即生效、零拷贝。
- **产物格式**：双格式产出 —— 构建同时产出 `*.umd.js` 与 `*.esm.js`，清单带 `type` 字段，前端 ESM 优先加载、UMD 兜底。

## 产品概述

建立「组件库构建产物（双格式）→ 上传注册 → 数据库存储 → 后端清单接口 → 前端动态加载」的完整闭环：

- 组件库构建时生成 `dist/manifest.json` 组件清单（含 `type`、主 `url` 与 `fallbackUrl`）
- 上传接口一次完成「文件落盘 + 清单写入数据库」，幂等 upsert
- 后端 `GET /api/components` 从数据库返回组件清单（遵循 `docs/api-contract.md` 契约，扩展 type/fallbackUrl）
- 后端 `/umd/**` 多位置静态资源映射（上传目录优先、组件库 dist、组件库根目录的 vue.js / vue.esm-browser.js）
- 拖拽前端适配双格式加载：ESM（`import()` + import map）优先，UMD（`<script>` + 全局变量）兜底

## 核心功能

- 组件库双格式构建（UMD + ESM）并自动生成带 `type`/`fallbackUrl` 的组件清单
- 清单一键同步：默认仅元数据（开发期配合静态映射）；`--upload` 模式连文件一起上传（生产/跨机）
- 后端 multipart 上传接口：文件落盘 + 数据库 upsert
- 后端组件清单查询接口与 `/umd/**` 静态资源服务
- 前端按 `type` 动态加载组件，ESM 失败自动回退 UMD

## 技术栈选择

- **组件库侧**：沿用现有 Vue 3.5.29 + Vite 7 + Node 脚本体系（ESM 模块）；Node 18+ 内置 `fetch`/`FormData`/`Blob`，无需新依赖
- **后端侧**：复用 `draggable-end` 现有技术栈 —— Spring Boot 4.1.1 + Java 21 + MyBatis-Plus 3.5.17（spring-boot4-starter）+ MySQL + Lombok（`application.yaml` 已配置 `jdbc:mysql://localhost:3306/draggable`、全局 `id-type: assign_id`）
- **前端侧**：沿用 Vue 3.5.29 + Vite；新增 import map + 动态 `import()` 加载 ESM 组件
- **双格式构建**：Vite lib 模式 `formats: ['umd', 'es']` 一次构建产出两种格式；`external: ['vue']`；Vue ESM 浏览器构建使用 `vue/dist/vue.esm-browser.js`（vue 包自带）

## 实现思路

核心策略：**构建即产出清单、上传即落盘入库、查询即读库返回、双格式加载**，组件元数据（title/description）的单一事实来源收敛到组件库 `meta.js`，消除 mock 插件硬编码的双份维护问题。

1. **组件库 `meta.js`**：登记每个组件的 `title`/`description`（key 与组件文件名一致）。
2. **`build.js` 双格式构建**：Vite lib 模式同时产出 `*.umd.js` 与 `*.esm.js`；CSS 内联注入逻辑对两种产物统一处理（读取 CSS → 注入 `<style>` 脚本到产物头部 → 删除独立 CSS 文件）；构建后生成 `dist/manifest.json`。
3. **`vue.esm-browser.js` 就位**：从 `node_modules/vue/dist/` 复制到组件库根目录（与 `vue.js` 并列），供 import map 映射与后端静态映射。
4. **`sync-db.js` 双模式**：默认仅 POST `{ components: manifest }` JSON（开发期文件走静态映射零上传）；`--upload` 用 multipart 附 `dist/*.umd.js`、`*.esm.js` 与 `vue.js`、`vue.esm-browser.js`。
5. **后端**：`schema.sql` 自动建 `component` 表（含 `type`/`fallback_url`）；`POST /api/components/sync`（multipart）解析 manifest + 落盘文件 + 按 `name` upsert；`GET /api/components` 查库返回契约结构；`WebConfig` 对 `/umd/**` 配置多 location 静态映射。
6. **前端 ESM 适配**：本地 `index.html`（gitignore 文件）增加 import map 映射 `vue` → `/umd/vue.esm-browser.js`；`umdLoader.js` 升级为按 `type` 加载的统一 loader；`useComponentRegistry` 改调统一 loader；mock 插件与页面导出 HTML 同步适配双格式。

## 关键技术决策

- **放弃纯"扫描目录"方案**：目录中的 `.umd.js` 只有文件名，没有 `title`/`description`（面板展示必需），Java 扫描拿不到这些元数据；强行扫描只能靠命名约定或后端再维护一份元数据（双份维护）。因此数据层必须由组件库构建时产出并主动同步。
- **上传接口单次完成"落盘 + 入库"**：原子性强、避免"文件在库不在"的不一致；`name` 唯一键保证 upsert 幂等，重复同步不产生脏数据。
- **ESM 为主、UMD 兜底**：`type: 'esm'`、`url` 指向 `.esm.js`、`fallbackUrl` 指向 `.umd.js`；前端 loader 在 `import()` 失败（如 import map 未就绪/跨域问题）时自动回退 `<script>` 加载，保证兼容性。
- **浏览器原生 ESM 裸导入约束**：ESM 产物含 `import { ... } from 'vue'`，浏览器不支持裸模块名，必须通过 import map 将 `vue` 映射到 `vue.esm-browser.js`；动态加载需 `new URL(url, location.origin).href` 构造绝对地址。
- **ID 策略**：主键用 MyBatis-Plus 全局 `assign_id`（雪花），与现有配置一致；`name` 作业务唯一键。
- **契约兼容扩展**：`ComponentItem` 新增 `type`/`fallbackUrl` 可选字段，既有字段不变，前端与 mock 插件均兼容。

## 实现注意事项

- `scripts/build.js` 为 ESM，可直接 `import` 新增的 `meta.js`；`manifest.json` 的 `id` 必须与 `name` 一致（契约要求）。
- ESM 产物头部可注入 CSS IIFE（合法语句），尾部 `export` 不受影响；CSS 内联需同时处理 umd/es 两个文件名（`*.umd.js` 与 `*.esm.js`），现有构建脚本中"非 UMD 文件移入 assets"的逻辑需相应调整（避免把 `.esm.js` 误移走）。
- `spring.sql.init` 对 MySQL 非嵌入式数据库默认不执行，需显式 `mode: always` + `CREATE TABLE IF NOT EXISTS` 保证重复启动幂等。
- `WebConfig` 静态资源 `file:` 路径目录末尾必须带 `/`；Windows 绝对路径通过 `application.yaml` 的 `app.*` 配置项覆盖，不硬编码；`/umd/**` 多 location 按顺序查找、第一个命中返回（上传目录优先）。
- `POST /api/components/sync` 的 `manifest` 字段为 JSON 字符串（multipart 中不可直接传对象），需 `ObjectMapper.readValue` 解析并校验；文件 part 文件名需白名单校验（仅 `*.umd.js` / `*.esm.js` / `vue.js` / `vue.esm-browser.js`）防目录穿越。
- 前端 `index.html` 被 `.gitignore` 忽略（`*.html`），是本地文件，修改它不影响版本库；`main.js` 中 `window.Vue = Vue` 仍需保留（UMD 兜底加载依赖全局 Vue 同一实例）。
- `mock-backend.js` 的 `COMPONENT_META` 需增 `type` 字段，`listComponents()` 生成 esm 优先清单，`/umd/*` 白名单放行 `.esm.js` 与 `vue.esm-browser.js`；`renderPageHtml()` 与 `pageExporter.js` 按 `type` 生成 `<script type="module">` + import map 或普通 `<script>`。
- 同步为构建期低频操作、组件数量级小，`GET /api/components` 单表全量查询无性能瓶颈，无需缓存。

## 关键数据结构

### manifest.json（组件库构建产物，每组件一条）

```
[
  {
    "id": "CustomHead",
    "name": "CustomHead",
    "globalName": "CustomHead",
    "title": "自定义头部",
    "description": "支持标题、左右图片与吸顶开关的页面头部组件",
    "type": "esm",
    "url": "/umd/CustomHead.esm.js",
    "fallbackUrl": "/umd/CustomHead.umd.js"
  }
]
```

### component 表结构

```sql
CREATE TABLE IF NOT EXISTS `component` (
  `id`          BIGINT       NOT NULL AUTO_INCREMENT COMMENT '主键',
  `name`        VARCHAR(64)  NOT NULL COMMENT '组件名，即 UMD/ESM 文件名前缀（唯一）',
  `global_name` VARCHAR(64)  NOT NULL COMMENT 'UMD 全局变量名',
  `title`       VARCHAR(128) NOT NULL DEFAULT '' COMMENT '展示标题',
  `description` VARCHAR(512) NOT NULL DEFAULT '' COMMENT '组件描述',
  `type`        VARCHAR(16)  NOT NULL DEFAULT 'esm' COMMENT '主加载格式：esm | umd',
  `url`         VARCHAR(255) NOT NULL DEFAULT '' COMMENT '主格式文件访问路径',
  `fallback_url` VARCHAR(255) NOT NULL DEFAULT '' COMMENT '兜底格式文件访问路径',
  `created_at`  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_at`  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_name` (`name`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='组件注册表';
```

### 同步接口契约（新增，遵循既有错误格式）

```
POST /api/components/sync
Content-Type: multipart/form-data
字段:
  - manifest: JSON 字符串（ComponentItem[]，必填；解析失败返回 400 {code,message}）
  - 文件部分（可选）: *.umd.js / *.esm.js / vue.js / vue.esm-browser.js
响应 200: { "synced": n }
错误:     { "code": 400, "message": "..." }
```
